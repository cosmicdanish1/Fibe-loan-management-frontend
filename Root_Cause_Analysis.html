This document records the diagnosis, root causes, security updates, and final verification metrics regarding the LAN connection setup on the Client PC, enabling it to securely communicate with the central database on the Server PC.

📋 Root Cause Analysis Matrix

# Problem Symptom Root Cause Fix / Resolution
1 Ping requests timed out to Server PC IPs over direct cable connection. Subnet Mismatch: Client PC was actively routing traffic on Wi-Fi (subnet 10.104.28.x). The LAN Ethernet card defaulted to a link-local 169.254.x.x. Configured a Static IP 192.168.1.100 on the Client PC's Ethernet card. Successfully established connection to 192.168.1.50.
2 Dev mode app still routed API calls to localhost:3001. Hardcoded Dev Defaults: Electron's main process had isDev hardcoded to return localhost, completely bypassing server-config.json in dev mode. Modified getBackendOrigin() and get-server-url IPC handler to evaluate and read server-config.json in development mode.
3 File reading failed in specific launch flows (e.g. from Batch files). Working Directory Ambiguity: Using process.cwd() is relative to the start command directory, causing failures when Electron was spawned via HMR. Configured multi-path scanning to look up app.getAppPath(), process.cwd(), and folders relative to __dirname.
4 Web requests blocked inside the app's browser console. CSP Policy Constraint: The Content Security Policy connect-src header in dev mode restricted traffic exclusively to local hostnames. Expanded the connect-src CSP header in main.ts to allow connections to external LAN IPs on http://*:3001.

🔍 Detailed Issues & Resolution Verification

🛠️ 1. Subnet Connection Success

Symptom:Destination host unreachable.
Diagnosis:Client LAN adapter was unassigned (APIPA fallback) due to lack of a DHCP server.
Fix:Configured Static IP 192.168.1.100. Pinging 192.168.1.50 succeeded instantly.
Pinging 192.168.1.50 with 32 bytes of data: Reply from 192.168.1.50: bytes=32 time<1ms TTL=128 Reply from 192.168.1.50: bytes=32 time<1ms TTL=128

⚙️ 2. Dev-Mode Config Resolution

Symptom:Vite app defaulted to localhost:3001.
Diagnosis:isDev boolean checked in Electron automatically bypassed configuration file checks.
Fix:Re-coded Main Process to check for root configurations before returning defaults.
if (isDev) { const devCfg = readProjectRootServerConfig(); if (devCfg) return `http://${devCfg.serverIP}:3001`; return 'http://localhost:3001'; }

🔒 3. Content Security Policy (CSP) Fix

Symptom:Requests blocked in renderer console.
Diagnosis:connect-src header lacked clearance for remote LAN IP addresses on port 3001.
Fix:Allowed http://*:3001 inside connect-src in main.ts development CSP configuration.
isDev ? "connect-src 'self' http://localhost:* ws://localhost:* wss://localhost:* http://*:3001 http://localhost:3001" : "connect-src 'self' http://*:3001 http://localhost:3001"
🟢 Verification & Proof of Concept

Server-Side Handshake Success: When testing from the Client PC browser, the Server PC's NestJS backend successfully logged a GET /favicon.ico - 404 request. This is concrete proof that the LAN handshake is fully operational and the Server PC's firewall is successfully letting traffic through!
